## src/services rules
- One file per domain (`pacientes`, `prontuario`, `guias`, `arquivos`): Zod schema + typed write functions + that domain's `queryOptions`. Components call them through mutation hooks in `src/hooks/use-<domínio>.ts`, never `supabase.from(...)` writes directly for refactored domains. Why: one validated path per write, so screens can't skip the rules.
- Every write validates with `validar(schema, dados)` and every response goes through `garantir(res)`; both throw `ErroServico` (friendly message + `campo`/`campos` for highlighting). UI shows `mensagemDeErro(e)`. Shared field rules (CPF, phone, TUSS, guide codes, CID, money, dates, upload type/size) live in `src/lib/validacao.ts` with tests.
- Private files: paths are always `{clinica}/{pasta}/...` built by `caminhoArquivo`, uploads go through `enviarArquivo` (type/size checked), and files open only via `abrirArquivoPrivado`/`linkTemporario` (signed URL clamped to 60–300 s, generated on click). Never call storage `remove` for files a row points to — the database keeps them for retention; `desfazerEnvio` is only for an upload whose row insert failed.
- Patient clinical data (diagnosis, CID, allergies, medication) is read/written only via `paciente_dados_clinicos` (`dadosClinicosQuery`/`salvarDadosClinicos`); `CadastroPaciente` excludes those columns, LGPD fields and metadata. Evolutions are created only with `registrarEvolucao` (RPC, goals in the same transaction); corrections only with `registrarAdendo`.
- Governance page (`$clinica/seguranca`, gestor only, with the audit trail at `seguranca/auditoria`; old `/auditoria` redirects) reads one SECURITY DEFINER RPC `painel_governanca` (counts and catalog checks only, no clinical content); pass/attention/critical rules per LGPD/ISO/HIPAA/SOC 2 control live in `src/lib/conformidade.ts` with tests. Add a check there when a new safeguard is added.
